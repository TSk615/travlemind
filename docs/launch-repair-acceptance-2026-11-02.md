# 2026-11-02 上线验收阻断修复（候选版本）

这次修复针对真实任务 `job_635ffd51a05baadca5bd`，不以此前的分段测试代替完整验收。

## 确认的问题

- 初稿可解析，但进站项目的 45 分钟跨度被同时分配了 45 分钟转场与 40 分钟缓冲；这是真实时间冲突，必须由规划器修改，后端不会偷偷挪动时间。
- 路线汇总的 `arrival_date` 被当成具体班次的确定时刻约束，错误拒绝了明确标记“班次待确认”的跨夜建议窗口。修复后仍校验路线最短耗时；若选用了有来源的具体班次，则严格核对班次起止时间与到达日期。未确认窗口不会因此获得“已核验”标记。
- 局部冲突却要求模型重写整份五日行程，单次修复又生成重复 JSON 字段，导致最终失败。

## 修复边界

- 局部修复只返回获准项目的字段更新、获准日期的留白，以及显式授权的住宿费用。模型不再重写全部日期与项目。
- 后端将补丁合并到原稿副本，保留无关日期和字段；依赖转场只能改时间，不能更换地点或预订。
- 重复 JSON 字段、重复项目更新、越权字段、多个 JSON 对象、非有限数、空补丁均拒绝，不选“最后一个字段”冒充修好。
- 合并后仍执行原有完整 schema 和可执行性校验。初稿格式损坏或属于全局结构错误时，保留原来的全量修复路径。
- 不增加模型调用次数或共享修复预算；完整研究证据仍保留，不通过截断来源掩盖问题。
