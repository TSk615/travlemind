# TravelMind AI 产品功能与交互简报

这份文档用于交给 UI 设计 AI，帮助它理解 TravelMind AI 的产品定位、核心功能、页面结构、用户流程和关键交互，从而设计完整可落地的界面。

## 1. 产品定位

TravelMind AI 是一个 AI 旅行规划工作台。它帮助用户从“想去哪、几天、预算、兴趣偏好”等模糊需求开始，生成结构化旅行计划，并继续完成搜索资料核验、行程优化、预算拆解、预订提醒、图片补全、PDF/Markdown/JSON 导出和社区分享。

产品不是单纯的“旅游攻略展示站”，而是一个围绕旅行计划生命周期的 AI 工具：

- 灵感进入：用户输入目的地、出发地、日期、预算、人数、兴趣、节奏、交通方式。
- AI 生成：系统异步生成每日行程、预算、风险、交通建议、天气提示、引用来源。
- 人工调整：用户可以手动编辑每日行程，也可以用自然语言让 AI 局部优化。
- 资料增强：系统可通过搜索服务和小红书来源补充可信资料、图片和攻略依据。
- 输出分享：用户可以导出 PDF/Markdown/JSON，也可以发布到社区。
- 个性配置：用户可配置 LLM、搜索服务、图片生成服务和小红书账号绑定。

## 2. 用户角色

### 普通用户

普通用户是主要使用者，可以注册登录、创建旅行计划、生成行程、优化行程、导出文件、生成旅行图片、浏览社区攻略、发布自己的行程到社区。

### 管理员

管理员可以进入后台管理用户、行程、社区帖子和异步任务。管理员界面偏运营后台，重点是检索、筛选、查看详情、禁用用户、删除内容、查看任务状态。

## 3. 信息架构

主导航包含：

- 首页：产品介绍和核心 CTA。
- 我的行程：用户创建过的旅行计划列表。
- 新建行程：创建旅行需求，支持表单模式和 AI 对话模式。
- 攻略社区：浏览其他用户发布的旅行计划快照。
- AI 生图：生成、管理、公开或 remix 旅行视觉图。
- 模型设置：配置 LLM、搜索、图片生成、小红书账号。
- Admin：管理员后台，仅管理员可见。
- LLM Demo：独立调试页，不走普通 App Shell，偏开发/调试用途。

全局还有：

- 登录/注册入口。
- 中英文语言切换。
- 当前用户信息和登出。
- 后台任务提示 Toast，例如行程生成、图片增强、导出任务正在运行。

## 4. 核心用户流程

### 流程 A：从零创建并生成行程

1. 用户从首页点击“开始规划”或从导航进入“新建行程”。
2. 用户选择表单模式或对话模式。
3. 表单模式下填写出发地、目的地、日期、预算、人数、兴趣、住宿偏好、旅行节奏、交通方式。
4. 对话模式下，用户用自然语言描述需求，AI 逐步追问缺失字段，并实时补全右侧草稿。
5. 用户点击“创建行程”只保存基础需求，或点击“创建并生成”立即启动 AI 行程生成任务。
6. 系统创建 Trip，进入行程详情页，并通过 Job 状态显示生成进度。
7. 任务完成后，展示完整行程、预算、风险、天气、交通和来源依据。

### 流程 B：查看和编辑行程

1. 用户进入“我的行程”列表。
2. 每张行程卡展示标题、目的地、日期范围、预算、人数、社区发布状态。
3. 用户打开行程详情。
4. 如果还没有行程内容，页面提示用户点击生成。
5. 如果已有行程，页面展示概览指标、每日行程、预算、预订提醒、搜索引用、AI 执行轨迹。
6. 用户可以点击“编辑行程”手动修改每日标题、摘要、活动、时间、地点、备注、费用等。
7. 保存后行程内容更新。

### 流程 C：AI 优化行程

1. 用户在行程详情点击“优化行程”。
2. 弹出优化弹窗。
3. 用户可以选择快捷优化指令，例如调整节奏、降低预算、增加亲子活动、优化交通。
4. 用户也可以输入自定义指令。
5. 用户可以上传外部攻略文本，作为 AI 优化参考。
6. 用户可以从社区选择其他攻略作为参考来源。
7. 提交后系统启动 refine job。
8. 页面显示后台任务状态，完成后更新行程。

### 流程 D：资料搜索与来源可信度

1. 行程生成和优化会结合官方来源、用户链接、远程搜索服务、小红书来源。
2. 搜索结果有评分结构：可信度、内容质量、新鲜度、广告风险、最终分。
3. Debug 模式下，行程详情可展示搜索资料、grounding references、agent pipeline。
4. 普通 UI 应该把“引用来源”和“可信度”设计得清晰但不喧宾夺主。

### 流程 E：图片增强和 AI 生图

1. 行程详情支持“图片增强”，为行程中的活动项补充图片。
2. AI 生图页面支持 text-to-image 和 image-to-image。
3. 用户输入 prompt、优化 prompt、negative prompt、参考 URL、上传参考图或源图。
4. 用户可以先“优化提示词”，再“生成图片”。
5. 图片生成是异步任务，页面显示任务状态。
6. 生成结果进入个人图库。
7. 用户可将图片设为公开或私密。
8. 公共图片进入图片 Feed。
9. 用户可复制 prompt、载入表单、remix 他人作品。

### 流程 F：社区发布

1. 用户在行程详情点击“发布到社区”。
2. 弹窗中填写分享说明，最多约 280 字。
3. 发布后系统保存当前行程快照，而不是直接引用实时行程。
4. 如果原行程后来被修改，社区发布状态会显示“已过期/需刷新”。
5. 用户可以刷新社区帖子，使社区快照同步最新行程。
6. 社区 Feed 展示封面图、标题、目的地、摘要、作者、日期、预算、人数、兴趣标签和分享说明。
7. 社区详情页展示完整行程快照、分享说明、预算、每日安排、AI 执行轨迹和引用来源。

### 流程 G：导出

1. 用户在行程详情点击“导出 PDF”或多格式导出。
2. 系统创建导出任务。
3. 导出详情页展示任务类型、状态、阶段、进度、更新时间、时间线。
4. 任务完成后显示生成文件列表，例如 PDF、Markdown、JSON。
5. 用户点击文件链接打开或下载。

### 流程 H：模型和服务配置

1. 用户进入设置页。
2. 配置 AI 行程模型：协议、Base URL、模型、API Key、接口格式、agent provider。
3. 支持 OpenAI Responses、OpenAI-compatible Chat Completions、Gemini、Claude、NewAPI、NeiAPI 风格端点。
4. 用户可以拉取模型列表、测试连接。
5. 配置搜索服务：GrokSearch MCP 或 Tavily API，Base URL、API Key、超时时间、小红书来源开关。
6. 配置图片生成服务：OpenAI-compatible、HuggingFace、Gitee AI、ModelScope、A4F 等。
7. 可绑定小红书账号，用于小红书素材/图片来源增强。

## 5. 页面说明与关键交互

### 首页

目标：让用户理解产品价值，并快速进入新建行程或社区。

建议内容：

- Hero 标题：强调“从灵感到可执行旅行计划”。
- 副标题：说明 AI 会生成每日行程、预算、预订提醒、引用来源和可导出文件。
- 主 CTA：开始规划。
- 次 CTA：浏览社区灵感。
- 能力卡片：AI 行程规划、可信资料搜索、预算与预订提醒、图片增强、PDF 导出、社区分享。
- 流程条：描述“填写需求 -> AI 生成 -> 优化确认 -> 导出/分享”。

### 登录/注册页

目标：让用户进入受保护功能。

交互：

- 登录/注册 Tab 切换。
- 注册时需要昵称、邮箱、密码。
- 登录时需要邮箱、密码。
- 支持 redirect，登录后回到之前想访问的页面。
- 表单应有 loading、错误提示、disabled 状态。

### 我的行程页

目标：管理所有旅行计划。

内容：

- 顶部标题和“新建行程”按钮。
- 空状态：引导创建第一个行程。
- 行程卡片：标题、目的地、日期、预算、人数、社区发布状态。
- 操作：打开行程、删除行程。

注意：

- 删除操作是危险操作，需要明确视觉区分，最好有确认。
- 卡片应突出目的地和日期，因为这是用户扫描列表的主要依据。

### 新建行程页

目标：收集旅行需求，并创建/生成行程。

布局建议：

- 左侧主输入区，右侧实时草稿摘要。
- 顶部模式切换：表单模式 / AI 对话模式。
- 顶部工具：恢复示例草稿、清空表单。

表单字段：

- 出发地 origin。
- 目的地 destination。
- 开始日期 start_date。
- 结束日期 end_date。
- 预算 budget。
- 旅行人数 travelers。
- 兴趣 interests，逗号分隔或标签输入。
- 住宿偏好 accommodation_preference。
- 旅行节奏 pace，例如轻松、均衡、紧凑。
- 交通方式 transport_mode，例如公共交通、自驾、混合。

核心操作：

- 创建行程：只保存需求。
- 创建并生成：保存后立即启动 AI 生成。
- 对话模式发送消息：AI 追问和补全草稿。
- 对话模式达到 ready_to_create 后，允许创建并生成。

状态：

- 字段校验错误。
- 对话发送中。
- 创建中。
- 生成中。
- 草稿缺失字段提示。

### 行程详情页

目标：这是产品核心工作台。用户在这里查看、生成、优化、编辑、增强、导出和发布行程。

顶部信息：

- 行程标题。
- 日期范围。
- 预算。
- 人数。
- 操作按钮：生成行程、优化行程、发布/编辑社区帖子、导出、删除。

核心模块：

- 概览：摘要、总预算估算、天数、风险数、预算状态。
- 当前任务：任务类型、阶段、进度、更新时间、时间线。
- 行程 Brief：出发地、目的地、日期、预算、人数、兴趣、住宿偏好、节奏、交通方式。
- 精准预算：预算上限、预计总花费、剩余/超支、分类拆解、逐项费用。
- 交通与预订：跨城交通、本地交通、推荐方案、预订窗口、官方链接、提醒事项。
- 每日行程：按 Day 分组，每天有标题、摘要、总花费、天气、活动列表。
- 活动项：时间、类型、名称、地点、评分、备注、预订信息、图片、图片状态。
- 视觉资料：来自小红书或搜索引用的图片资料。
- 搜索/引用资料：可信来源卡片、平台、标题、摘要、评分、链接。
- AI 执行轨迹：provider、workflow、每个 agent 的状态、模型、输出摘要、引用。

主要交互：

- 生成行程：启动 generate job。
- 优化行程：打开优化弹窗，提交 refine job。
- 图片增强：启动图片 enrich job。
- 手动编辑：打开 itinerary editor，增删天数和活动项，保存或取消。
- 发布社区：填写分享说明并发布快照。
- 刷新社区：当源行程更新后，同步社区快照。
- 导出：启动 export job。
- 删除：删除当前行程。

设计重点：

- 行程详情信息密度很高，必须有清晰分区、锚点导航或 sticky 目录。
- AI 任务状态要明显，因为生成/优化/导出/图片增强都是异步。
- “可编辑内容”和“AI 生成依据”需要视觉区分，避免用户不知道哪里能改。
- 预算和预订提醒是决策信息，应比调试信息更突出。

### 导出详情页

目标：让用户看到导出任务进度并获取文件。

内容：

- 任务类型。
- 当前状态：queued/running/completed/failed。
- 当前阶段。
- 进度百分比。
- 更新时间。
- 任务时间线。
- 完成后的文件列表：文件名、类型、大小、打开链接。
- 返回行程按钮。

### 攻略社区 Feed

目标：让用户浏览他人发布的旅行攻略，获取灵感。

卡片内容：

- 封面图。
- 标题。
- 目的地。
- 行程摘要。
- 分享说明。
- 日期范围。
- 预算。
- 人数。
- 兴趣标签。
- 作者和发布时间。
- 打开详情入口。

设计重点：

- 更像“旅行灵感瀑布/卡片流”，但不要变成纯图片社区，因为核心仍是结构化行程。
- 分享说明可以用引用式视觉表现。

### 社区帖子详情页

目标：展示一份已发布行程快照。

内容：

- 标题、目的地、作者、发布时间、更新时间。
- 分享说明。
- 行程基础信息。
- 每日行程。
- AI 执行轨迹。
- 引用来源。

注意：

- 这是快照，不一定等于用户当前最新行程。
- UI 可以表达“来自某用户的计划副本/发布版本”。

### AI 生图页

目标：生成旅行相关视觉图，并管理个人和公开图片。

主要区域：

- Hero/说明区。
- 创建面板：可见性、模式、prompt、optimized prompt、negative prompt、参考 URL、源图上传、参考图上传。
- 操作：优化提示词、生成图片、刷新。
- 当前任务卡片：图片生成 job 状态。
- 公共 Feed：公开图片作品。
- 我的图库：个人生成记录。
- 筛选：模式、状态、可见性。

图片卡片操作：

- 复制 prompt。
- Remix。
- 载入表单。
- 切换公开/私密。

状态：

- draft/queued/running/completed/failed。
- private/public。
- text_to_image/image_to_image。

### 设置页

目标：让用户配置外部 AI 和搜索能力。

模块：

- AI 行程模型设置。
- 搜索服务设置。
- 图片生成服务设置。
- 小红书账号绑定。

关键交互：

- 刷新当前设置。
- 选择 provider/protocol。
- 输入 base URL、model、API Key。
- 拉取模型列表。
- 测试 LLM 连接。
- 保存设置。
- 绑定/解绑小红书。
- 显示 API Key 已配置但只展示 masked 状态。

设计重点：

- 这是高级配置页，需要清晰分组和解释文案。
- API Key 字段要让用户知道“留空代表不修改密钥”。
- 连接测试结果应有明确成功/失败反馈。

### 管理后台

目标：运营和管理系统数据。

模块：

- 用户管理。
- 行程管理。
- 社区帖子管理。
- 任务管理。

通用交互：

- Tab 切换模块。
- 搜索和筛选。
- 表格列表。
- 分页。
- 点击行进入详情。
- 关闭详情回到列表。

管理操作：

- 禁用/启用用户，需要 reason。
- 删除行程，需要 reason。
- 删除社区帖子，需要 reason。
- 查看任务 payload、result、timeline、错误信息。

设计重点：

- 后台应偏实用，不需要强情绪化视觉。
- 危险操作必须清晰标红并确认。

### LLM Demo 调试页

目标：开发/高级用户测试模型、搜索和图片代理。

功能：

- LLM 聊天测试，支持 stream。
- 搜索服务探测。
- 图片搜索探测。
- 小红书图片探测。
- Tavily 图片/搜索探测。
- 展示请求结果、图片候选、JSON 原始数据。

设计建议：

- 可以作为内部工具处理，不必纳入主产品视觉重点。
- 信息密度高，适合左右分栏：配置区 + 结果区。

## 7. 异步任务状态

系统中很多操作是异步 Job：

- 生成行程。
- 优化行程。
- 图片增强。
- 图片生成。
- PDF/多格式导出。

Job 状态：

- queued：已排队。
- running：运行中。
- completed：完成。
- failed：失败。

UI 需要展示：

- 状态标签。
- 阶段 stage。
- 阶段说明 stage_message。
- 进度 progress_percent。
- 更新时间。
- 时间线 timeline。
- 错误信息 error_message。

建议设计统一的 AI/任务状态组件，用于行程详情、AI 生图、导出详情和全局 Toast。

## 8. 搜索和可信来源设计

SearchDocument 字段：

- platform：来源平台。
- title：标题。
- url：链接。
- summary：摘要。
- destination/place/category：地点相关信息。
- opening_hours/price_hint/address：实用信息。
- author/published_at/engagement_hint：社交来源信息。
- image_urls：图片。
- source_type：来源类型。
- scores：可信度评分。

评分包含：

- trust_score：可信度。
- quality_score：质量。
- freshness_score：新鲜度。
- ad_score：广告风险。
- final_score：最终分。
- reasons：评分原因。

UI 建议：

- 普通用户只展示“可信来源”“更新时间”“官方/社区来源”等简化标签。
- Debug 或高级区域再展示完整评分结构。
- 来源卡片应能打开原链接。

## 9. 设计语言建议

产品气质建议：

- 智能但不冰冷。
- 像旅行规划师，而不是后台表单系统。
- 有“地图、时间线、票据、攻略手帐”的感觉。
- AI 状态可以有轻微灵动感，但不要满屏科技炫光。

视觉关键词：

- 旅行工作台。
- 温暖纸张。
- 清晰卡片。
- 行程时间线。
- 可信来源。
- AI 辅助正在工作。
- 可执行计划。

推荐页面结构模式：

- 首页：叙事 Hero + 能力卡 + 流程说明。
- 新建行程：Workbench，左输入右摘要。
- 行程详情：List/Detail + sticky 锚点导航 + 时间线。
- 社区：卡片 Feed。
- AI 生图：创建面板 + Gallery。
- 设置：分组表单。
- 管理后台：Tabs + Filter + Table + Detail。

## 13. 一句话产品总结

TravelMind AI 是一个面向真实出行决策的 AI 旅行规划工作台，用户可以用表单或对话输入旅行需求，生成可执行的多日行程，并持续完成资料核验、预算控制、预订提醒、视觉增强、社区分享和文件导出。
