# 2026-11-02：搜索兜底与生成进度修复

## 用户可见变化

- 正常生成过程只显示中文步骤、必要进度和简短说明，不再展示角色英文介绍、工具名称、原始任务编号、内部时间线或服务器日志路径。
- 失败时显示中文提示，已保存行程不被覆盖；诊断详情仅限管理员主动打开，不支持普通用户用 `?debug=1` 查看。
- 未生成行程时不显示“重新补图”，公开体验账户不显示独立补图入口。

## 搜索与规划修复

1. Grok 搜索失败、超时、空回复或缺少来源时，自动使用 Exa；已有 Tavily / Firecrawl 来源保留并按链接去重，来源仍可通过同一搜索会话读取。
2. Grok 主搜索、整体搜索与 Exa 均有独立超时，防止 Grok 的等待占满外层工具预算而让兜底失去机会。
3. 景点研究结果为空时明确停止，不再花费规划请求生成空白行程，也不通过放宽数据结构校验伪装成功。
4. 规划与修复提示明确提供当日最早可出发时间（准备、接驳、候车缓冲），以及弹性时段不能与其他安排重叠的规则；保留原有严格校验，不自动修改真实班次。

## 实际验收范围

- **真实 Exa 验收**：仅在独立测试进程模拟 Grok 报错，Exa 约 1.27 秒返回 6 条带正文来源；同一会话的来源缓存读取验证通过。没有改变线上 Grok 配置。
- **失败任务的分段复测**：重新执行景点研究，得到 24 个候选；复用此前天气、住宿与交通资料。首次规划通过 JSON 结构校验，但时间安排仍有冲突；补充明确时间约束后，在一次修复预算内得到五天非空行程，通过结构与可执行性校验并成功组装结果。
- 分段复测在独立审计进程执行，没有新建公开体验任务，没有扣减体验次数，也没有覆盖原始失败记录。
- **以上不是全新用户从头生成、图片、导出全链路成功率保证。** 第三方搜索和模型仍可能限流、超时或给出无效结果，失败仍应如实提示，不以空结果冒充成功。

## 配置与隐私

真实 Exa Key 仅存服务器私密环境文件，不进入 Git、README、网页或前端包。配置占位符与超时说明见 [GrokSearch 与 Exa 配置](groksearch-local-setup.md)。

## 旧失败任务的继续生成

已耗尽共享修复预算的任务不再显示“继续生成”。直接调用该检查点的重试接口也会在创建任务和扣额度之前返回中文说明，要求重新生成；普通的断网、进程中断等可恢复失败仍保留检查点续跑能力。原失败记录不被改写为成功。
