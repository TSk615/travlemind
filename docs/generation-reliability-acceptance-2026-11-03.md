# 生成链路稳定性修复验收（2026-11-03）

> 后续仍出现结构与混合冲突失败；本文是早一轮的有限验收，不代表最终修复完成。请优先阅读 [后续修复与最终上线验收](planner-schema-stability-2026-11-03.md)。

## 修复内容

本轮修复生成链路本身，而非仅修改前端错误文案：

1. **分开格式与内容修复预算。** 首次规划后，最多允许一次格式修复、一次内容修复，总共不超过三次规划角色调用。格式修复不再吃掉重复景点、交通或时间冲突的修复机会。若内容补丁本身失败，不再额外重写完整行程来无限续命。
2. **严格解析。** 规划输出必须是单个完整对象，重复 JSON 字段、非法数值及多份冲突对象均拒绝。只在检查点保存错误代码、字符数、摘要和实际请求用量，不保存被拒绝的原始输出。
3. **接口层约束输出。** 首次规划启用 JSON 对象模式；局部内容补丁使用严格 JSON Schema。补丁为具备服务器项目标识、字段名和值的字段操作，不让模型重写整份行程；同一项目的同一字段不能修改两次，未经授权的项目与字段不能写入。
4. **补齐格式修复后的项目标识。** 格式修复后重新分配稳定项目标识，让后续内容冲突可以定位到具体项目。
5. **重复景点定向处理。** 以候选与证据为依据，让模型修正重复项目；后端不直接删景点凑成功。合并后仍执行原有结构、景点、时间、交通和证据约束检查。
6. **只修硬冲突，严格限制权限。** 留白冲突只授权受影响日期的留白字段，不能改任何项目；分钟分配冲突只授权用途分配字段。软提示和未知信息继续作为待核验风险保留，不再触发对已通过硬校验草稿的重排。
7. **版本和实际用量可追踪。** 新工作流标记为 `trip-generation.reliable-v3`，保留各次规划与修复调用的实际用量。总调用上限指规划角色调用次数，HTTP 瞬时错误重试仍受既有请求预算约束。
