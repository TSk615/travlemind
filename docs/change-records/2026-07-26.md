# 变更记录：2026-07-26

本次提交汇总了多个工作会话的成果，主线是把项目从 PoC 推向可运维：引入数据库迁移体系、安全加固、任务可靠性、POI 独立模型配置、CI 收紧，以及一轮针对 LLM 编排与图片链路的代码审查落地整改。

后端测试：136 passed（test_llm_orchestrator / test_llm_proxy / test_trip_image_enrichment / test_api_flow / test_export_service）。

## 1. 数据库与迁移（Alembic）

- 引入 Alembic 取代 `create_all` + 启动期手写 DDL：新增 `alembic.ini`、`migrations/`（0001 吸收式初始迁移，可直接纳管存量 SQLite 老库；0002 任务可靠性字段；0003 预算 Numeric 化）。
- `db/models.py` 删除 4 个 `_ensure_sqlite_*` 启动副作用函数；`job_service.py` 删除 `_JOB_SCHEMA_CACHE` ALTER TABLE 逻辑。
- `init_db()` 改为 `alembic upgrade head` + 历史明文凭据自动加密回迁。
- `env.py`：PostgreSQL 走 advisory lock 防并发迁移，SQLite 走 batch 模式；`fileConfig(disable_existing_loggers=False)` 修复应用 logger 被禁用的问题。
- 模型变更：`trips.budget` Float→Numeric(14,2)；`users` 新增 5 个 `poi_llm_*` 字段；4 个 api_key 列改用加密类型；`job_records` 新增 6 列 + 幂等唯一索引与恢复索引。
- 默认数据库切换为 PostgreSQL（compose 中升为必备服务）；引擎加 `pool_pre_ping`。
- 新增测试：`test_database_migrations.py`、`test_postgres_migrations.py`（真 PG 循环迁移，CI 挂 postgres:16 service）。

## 2. 安全加固

- 凭据静态加密（`core/credentials.py`）：Fernet + `EncryptedCredential` TypeDecorator，ORM 层透明加解密，带版本前缀。
- `RequestSecurityMiddleware`（`core/request_security.py`）：CSRF（Origin 白名单 + 双提交 Cookie）与限流（按路由+身份三档配额，Redis Lua 原子计数，内存兜底；生产环境 Redis 故障 fail-closed）。
- Cookie 策略配置化：secure/samesite 读配置，生产默认 Secure；新增 CSRF cookie 下发。
- 生产配置守卫：`environment=production` 启动即校验 9 项（密钥强度、https、CORS、非 SQLite、CSRF/限流开启等）。
- 新增测试：`test_request_security.py`、`test_security_configuration.py`；conftest 显式关闭测试环境的 CSRF/限流。

## 3. 任务可靠性

- 幂等：创建类端点支持 `Idempotency-Key` 头；arq 入队去重。
- 重试：瞬时故障识别 + 指数退避（上限 300s）；worker 转 arq Retry。
- 租约与心跳：原子领取任务、心跳循环、worker 启动时僵死任务恢复。
- 取消：`POST /jobs/{id}/cancel`，handlers 8 个节点检查取消；终态防回写。
- 断点续跑：失败时保存 orchestrator checkpoint，`POST /jobs/{id}/retry` 从失败角色续跑；JobResponse 暴露 `can_resume` 等字段。
- `JobStatus` 扩为 6 态（+retrying/cancelled），前后端类型同步。
- worker 依赖重构：改为 editable path 依赖 api 包，删除 sys.path hack，Dockerfile 层序修正。
- 新增测试：`test_job_reliability.py`。

## 4. LLM 配置与路由

- 用户级 POI 模型配置：5 个 `poi_llm_*` 设置字段，注入 poi/hotel/transport 三角色；「三项全填或全空」422 校验。
- `/llm/models`、`/llm/test` 支持 `scope: agent|poi`；poi 测试走流式规避长响应超时。
- Grok 直连环境变量回退（`TRAVELMIND_GROK_LLM_*`）。
- `HelloAgentsCompatibleLLM` 抽出为 `agents/helloagents_llm.py`。
- 新增 `POST /llm/poi-specialist-probe` 调试探针（供 LlmDemo 页）。
- prompts：poi_specialist(v10)、food_specialist(v1) 角色，全角色版本提升，schema 增加证据链字段。

## 5. LLM 客户端整改（services/llm/client.py）

- 400 不再盲目重试：可重试集合收敛为 408/429/5xx/网络异常。
- 保留并收窄「升级为流式重发」：仅 408/504、或响应体明确要求 stream 的 400。
- 有限退避重试（最多2次，1s/2s，429 读 Retry-After）；sleep 可注入便于测试。
- 注入 `_http_client` 时尊重 per-request timeout。
- 内部真流式读 SSE（read timeout 按 chunk 计），外部接口不变。
- usage token 解析与日志（OpenAI/Claude/Gemini 三格式）。
